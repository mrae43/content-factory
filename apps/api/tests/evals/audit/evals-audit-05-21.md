## 2. `storyboard_fields` defaults to deprecated field name `visual_prompt`

**File:** `tests/evals/schemas.py:210-213`

```python
storyboard_fields: List[str] = Field(
    default_factory=lambda: ["visual_prompt", "audio_cue"],  # ← deprecated name
    ...
)
```

**Glossary** (CONTEXT.md:142):

> `visual_description` — a text caption describing the visual element (icon/graphic)
> on the slide; displayed as a subdued subtitle. **Replaces the earlier `visual_prompt`
> concept** (which described a generated image — no longer applicable).

**Impact:**
- `assert_storyboard_fields()` in `tests/evals/assertions.py:71` checks that
  each storyboard item has the required fields. Because the default is
  `["visual_prompt", "audio_cue"]`, carousel slide decks validated with this
  assertion will look for `visual_prompt` instead of `visual_description`.
- Video storyboard items may still legitimately use `visual_prompt` (the Glossary
  says `visual_prompt` described a generated image that is "no longer applicable"
  — this suggests it should *not* be the default for any path).

## 6. `source_type=INFERRED` and `source_type=USER_PROVIDED` untested (behavioral gap)

**Glossary** (CONTEXT.md:11):
> tagged with a **source_type** enum (`USER_PROVIDED` from user-supplied URLs/raw
> text, `WEB_SEARCH` from Tavily results, `INFERRED` from the Retrieval Desk's
> synthesis)

**Eval 1.1** only tests `source_type=WEB_SEARCH` on Research Desk chunks.

Not tested anywhere in the evals:
- That `INFERRED` chunks are correctly created and tagged during Retrieval
  Desk synthesis (step 1 — "refined `INFERRED` chunks that are re-ingested
  into the vector store").
- That `USER_PROVIDED` chunks carry the correct `source_type` when ingested
  from user-supplied URLs/raw text.

**Impact:** The Retrieval Desk's Synthesis step could silently produce
`INFERRED` chunks with wrong source types, or fail to produce them at all,
and no eval would catch it.

domain document doesn't acknowledge. Either the glossary needs updating or the
enum value is vestigial.

## 9. No `FORMATTING` transition tested in the happy-path sequence

**Eval 7.1** (evals-criteria.md:320):
```
PENDING → RESEARCHING → RETRIEVAL → SCRIPTING → FACT_CHECKING_SCRIPT → FORMATTING → ASSET_GENERATION → COMPLETED
```

This is correct per the glossary. But:

- The golden dataset (`golden_dataset.json`) never uses `FORMATTING` or
  `RETRIEVAL` in any `expected_state_sequence`.
- The eval `schemas.py` `JobStatus` enum is missing `FORMATTING` (see #1).

The happy-path sequence defined in the criteria document references a state
that the eval schema doesn't recognise, and the dataset doesn't exercise.
